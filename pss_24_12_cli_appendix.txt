A.12.5 IPv4 address character (IPV4) definition
An IPv4 address (or IP address) is a 32-bit number written as four numbers separated by periods:
d.d.d.d where d=0..255
An IP address can also have a mask, which defines the IP subnetwork of the address.
There are two forms for subnet representation:
• CIDR mask (RFC 4632 and RFC 1519), which is a slash “/” character and decimal.
Example: /n where n=0..32
The CIDR mask defines how many bits from the left form the routing prefix.
• Dot-notation subnet mask, which has the same notation as an IP address.
Example: s.s.s.s where s=0..255
The subnet mask must be leading 1-bits (the routing prefix), followed by all 0-bits.
Examples:
• CIDR mask /24 is equivalent to dot-notation subnet mask 255.255.255.0
• CIDR mask /30 is equivalent to dot-notation subnet mask 255.255.255.252
Parts of the system (address definition, routes) use CIDR mask, subnet mask, or both.
IP addresses are used in various places, from provisioning an interface to setting a remote server.
Specifically, there are six different places IP addresses are used in provisioning:
1. Interface addresses for LAN and loopback interfaces
2. External addresses of servers and services
3. Cluster addresses
4. OCS addresses
5. Routing addresses (such as static routes, OSPF area IP ranges, and OSPF Virtual links)
6. Address in an Access Control List (ACL) pattern
Default addresses
On initial bootup, the system has two default IPv4 addresses set on the following interfaces:
• Loopback 172.16.1.1/32
• CIT 172.16.0.1/24
For all other interfaces, the default IPv4 address is 0.0.0.0/0.
Note: The two default addresses can be changed.
The loopback address is set during initial system installation. The CIT address should be
changed if it is set to redistribute (meaning it is advertised into OSPF) to avoid clashing with
the CIT addresses of other NEs.

Loopback interfaces (loopback, loopback1, GMRENODE, and GMRENOTIFY)

IPv6 address display
There are rules for text representation and standard shortcuts in displaying IPv6 addresses. For
displaying IPv6 addresses, the system follows most of the rules in RFC 5952.
• Letters: IPv6 addresses will be displayed with UPPERCASE letters for hex A-F (this differs from
RFC5952).
• Leading zeroes can be omitted for each 16-bit Field in the address.
Example: 2001:0db8::0002:0001 can be shortened to 2001:db8::2:1
• Use the double colon “::” to shorten several bytes of zeros as much as possible.
Example: 2001:db8:0:0:0:0:2:1 can be shortened to 2001:db8::2:1
In addition, the double colon “::”
− Can only be used once in an address.
− Cannot be used to shorten just one 16-bit 0 field.
− When there is an alternative choice in the placement of a double colon, the longest run of
consecutive 16-bit 0 fields must be shortened.
− When the length of the consecutive 16-bit 0 fields are equal (example: 2001:db8:0:0:1:0:0:1),
the first sequence of zero bits must be shortened. Example, 2001:db8::1:0:0:1 is the correct
representation.

address with embedded IPv4 address in “IPv6 address input” (p. 10977).
Example: ::13.1.68.3 or ::FFFF:129.144.52.38. Refer to RFC 4291 for the specific cases.

IPv6 prefix length
IPv6 addresses assigned to interfaces will have a prefix length, which is a “/” followed by a number
(example “/64”). Similar to the CIDR mask in IPv4 addresses, the IPv6 addresses prefix length and
has a format “/N”, where N=0-128. The prefix length (or subnet mask) is the only way to represent
the subnet in IPv6.
IPv4 subnet masks, like 255.255.255.0 are not allowed.
The IPv6 prefix is the part of the IPv6 address that represents the network identifier. The network
identifier appears at the beginning of the IPv6 address and the IPv6 prefix length, which begins with
a forward slash (/), shows how many bits of the address make up the network identifier. For
example, the address 1080:6809:8086:6502::1/64 means that the first 64 bits of the address
represent the network identifier; the remaining 64 bits represent the node identifier.
IPv6 interface address
Only certain IPv6 addresses are supported by the system for provisioning interfaces.
The system allows configuration of two IPv6 address types on supported interfaces:
• Global Unicast Address [ 2000::/3 ]
In IPv6, Global Unicast Addresses are the normal addresses that every node uses. These
addresses are assigned 001 as the 3 left-most bits in the 128 bit address, or 2000::/3.
• Unique Local Address (ULA) [ fc00::/7 though only fd00::/8 is currently used]
An IPv6 ULA is analogous to an IPv4 private address (example: 10.0.0.0/8, 192.168.0.0/16). A
ULA is globally unique but used locally within a site. It is intended for local communication and is
routable only within a set of cooperating sites (example: a lab).

The format of the Global Unicast Address is:
• Global Routing Prefix: The left-most part (48 bits) is the prefix allocated by the provider to a site.

The format of the Unique Local Address is:
• Must use fd for the first 8 bits
• Unique ID: assigned by site
• Subnet Identifier: subnet numbers within a site
• Interface ID: the right-most part (64 bits) is the host part, or interface identifier
Note: It is recommended that all addresses keep to this format and bit assignment; hence
each interface will have a 64 bit interface ID and /64 mask.
Prefix length on loopback and point-to-point addresses
The IPv6 address for a loopback should use a /128 prefix length, although others are allowed. For
point-to-point links, such as connections between ECs, the /127 or /126 prefix length can be used,
although others are allowed.
IPv6 link-local address
Every LAN interface will have a link-local address which is derived automatically from the media
access control (MAC) address using EUI-64 rules. Refer to RFC 4291 for details. This address is
not routable, though a directly attached host (such as a PC attached to the CIT interface) can
reference it.
The link-local address group is:
Link-Local Address [ FE80::/10 ]
The last 64-bit (host part) will be an IEEE EUI-64 identifier, which is derived from 48-bit MAC
address. EUI-64 will insert a hexadecimal “FF:FE” in the middle (after first 24 bits) of the MAC
address, and flip the 7th bit of the MAC. For example, the following 48-bit MAC, CA00.0E74.0008
will be the following EUI-64 identifier (insert FF:FE and flip the 7th bit): C800.0EFF.FE74.0008.
The IPv6 Link-Local address (short form) will be FE80::C800:0EFF:FE74:0008.

IPv6 address checks
The following rules apply when provisioning an IP address on any interface (for example, loopback
or LAN interfaces).
Loopback interfaces
The loopback interfaces that are assigned an IP address are subject to the following rules:
• Only the primary loopback interface can have an IPv6 address.
• Duplicate: A loopback address cannot be a duplicate of a LAN interface.
• Overlap: A loopback address should not overlap a LAN interface; a WARNING will be issued.
Additional interfaces
Any interface other than loopback that is assigned an IP address is subject to the following rules:
• Duplicate: An address cannot be a duplicate of another interface.
• Overlap: An interface should not be in the same subnet as another interface; a WARNING will be
issued.
Note: The Duplicate and Overlap rules apply even if one or both interfaces are down or
disabled.
Unlike IPv4 addresses, there are no exceptions for duplication for IPv6 addresses.

For view-only optical power values in the command outputs, the optical power values are reported
as follows:
• “” (blank) : power value is not available because card, port, or pluggable module is unequipped

• OFF: no optical power transmitted, laser off.
A.12.9 MAC addresses on external equipment
Customers should not assign the MAC addresses of 00:00:00:xx:xx:xx to external equipment (for
example, the DCN router connected to the OAMP interface) that is connected to the 1830 shelf
because 1830 systems use many of these addresses for internal Ethernet packets. Internal
Ethernet switches will prevent almost all packets with a Destination MAC address in this range from
being sent out on any external Ethernet interface.
A.12.10 Autonomous System Number definition
The system will use 4 Octet ASN (Autonomous System Number), as per RFC 6793, ranging from 0
to 4294967295. An ASN of zero (0) for the local ASN is used to indicate no ASN, for example, BGP
is disabled.
Any ASN in the range is allowed, (for example, no number shall be blocked). However, it is
expected that the user will follow IETF standards and will not use a reserved ASN, nor an ASN the
belongs to another Enterprise. An ASN reserved for private use is recommended if the system will
not be connected to the internet; otherwise a public ASN assigned to the customer should be used.

A.12.11 Software version definition
A software version is a release identifier that consists of a product name along with a date-based
release number.
<product>-<release-info>
<product> - Represents the product name
<release-info> - Represents the release date of the product
Allowed product names (<product>) are:
• 1830PSSECX
• 1830PSSECN
• 1830PSS4
Format of the release information (<release-info>) is yy.m-x:
• yy – Represents the last two digits of the year.
• m – Represents the month of the year (1 to 12 without leading zero).
• x – Increment for Maintenance releases. For a main release, x will be set to 0. And for
maintenance release, x will be increased.
Example
The release in December 2024: 1830PSSECX-24.12-0
The 3rd maintenance release for 24.12: 1830PSSECX-24.12-3
